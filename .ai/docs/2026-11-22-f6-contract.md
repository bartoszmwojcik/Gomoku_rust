## 2. Randomness (bit-exact; JS `Math.imul` and `>>> 0` semantics = Rust `u32` wrapping ops)

### 2.1 `seed_of(game_id: &str, move_number: u32) -> u32` (FNV-1a 32-bit)
```
text = format!("{game_id}:{move_number}")        // move_number 1-based: the move the bot is about to make
hash = 0x811c9dc5u32
for unit in text.encode_utf16():                  // charCodeAt = UTF-16 code unit; ids are ASCII (UUID, "arena-N") so bytes are identical
    hash ^= unit as u32
    hash = hash.wrapping_mul(0x01000193)
return hash
```
Vectors: `seed_of("game-1",7)=64945270`; `seed_of("arena-1",1)=2707506643`; `seed_of("a",1)=3686612585`; `seed_of("4d293981-7b3c-4f81-a1af-0a9e3bf3636b",1)=2326606625`, `(…,7)=2360161863`.

### 2.2 `Rng` = mulberry32, returns f64 in `[0,1)`
```
state: u32 = seed
next():
    state = state.wrapping_add(0x6D2B79F5)
    t = state
    t = (t ^ (t >> 15)).wrapping_mul(t | 1)
    t ^= t.wrapping_add((t ^ (t >> 7)).wrapping_mul(t | 61))
    return ((t ^ (t >> 14)) as f64) / 4294967296.0
```
(All shifts are LOGICAL on u32. The JS code mixes signed i32 and `>>>`, but every result is reduced mod 2^32, so plain u32 wrapping arithmetic is identical.)
`rng_for(game_id, n) = Rng::new(seed_of(game_id, n))`. R16: the seed depends only on game id and move number, so recomputing a move after a crash gives the same random draws.
Vectors: `Rng(42)` -> `0.6011037519201636, 0.44829055899754167, 0.8524657934904099`; `Rng(0)` -> `0.26642920868471265, 0.0003297457005828619`; `rng_for("arena-1", 2).next() = 0.9253256595693529`.
Tests to port (`seed.test.ts`): stable u32; differs by move and by game; same seed -> same 1000 values all in `[0,1)` with >990 distinct; different seeds differ; `rng_for` == `Rng::new(seed_of)`.

### 2.3 RNG consumption order (this decides all ties; keep EXACTLY)
- Opening reply (one stone on the centre): ONE draw `floor(rng * 8)`.
- Level 1: ONE draw `floor(rng * pool.len)`, only when no win and no block.
- Level 2: one draw PER ROOT CANDIDATE (all candidates, ascending cell order, before truncating to 20) for the tie-break, and then, only if no iteration completed, the level-1 fallback draws (one more) from the SAME rng. Nothing else draws.

## 3. Zobrist keys

Table size `450 = 225 cells * 2 colours`, index `cell*2 + colour` (0 black, 1 white). Two `i32` tables (high half / low half of a 64-bit key):
```
build(seed): rng = Rng::new(seed); for i in 0..450 { table[i] = (floor(rng.next() * 4294967296.0) as u32) as i32 }   // i.e. the next raw u32 of mulberry32 reinterpreted as i32
ZOBRIST_HI = build(0x9e3779b9)
ZOBRIST_LO = build(0x9e3779b9 ^ 0x5bd1e995)       // = 0xc5e6902c
```
(`rng.next() * 2^32` is exactly the u32 output, so you can keep the raw u32 and skip the float.) The two tables use the SAME generator sequence shape but different seeds, so HI != LO. Keys are independent of the move's `rng`.
Vectors (as i32): `HI[0..4] = [1541420728, 454851044, -1394616772, -352468386]`; `LO[0..4] = [-1984444241, -210222730, -2030773049, -815818552]`; `HI[449] = -754540446`, `LO[449] = -1217118521`.
`hash_hi ^= HI[cell*2+side]`, `hash_lo ^= LO[...]` on place AND on remove (XOR is its own inverse). Tests: 450 entries each; the 450 (hi,lo) pairs are distinct; HI != LO; table identical on reload.

## 4. `EngineBoard` (patterns.ts)

State: `cells: [i8;225]` (0 empty, 1 black, 2 white); `counts: [[i8;572];2]` stones of each colour per window; `score: [i64;2]`; `fours: [i32;2]`; `near: [i16;225]` stones within radius 2; `stones: u32`; `hash_hi, hash_lo: i32`.
Windows: for every `(x,y)` and axis in `[(1,0),(0,1),(1,1),(1,-1)]` the 5 cells `(x+dx*s, y+dy*s)`, s=0..4, kept only if `end_x = x+4dx < 15`, `end_y = y+4dy` in `0..15` (so for `(1,-1)`: `y >= 4`). Order of enumeration does not affect any result (all aggregates are commutative integer sums); keep per-cell lists of window ids. Cell with 20 windows at the centre, 3 in a corner (test).
`place(cell, side)` / `remove(cell)` -> `update(cell, side, ±1)`; `stones` ±1; `cells[cell] = side+1` / 0.
```
update(cell, side, delta):
  for w in windows_of(cell):
    other_count = counts[1-side][w]
    before = counts[side][w]; after = before + delta; counts[side][w] = after
    if other_count == 0:
        score[side] += W[after] - W[before]
        fours[side] += (after == 4) - (before == 4)
    if before == 0 || after == 0:                  // the other colour's window dies (place) or revives (remove)
        sign = if after == 0 { +1 } else { -1 }
        score[1-side] += sign * W[other_count]
        if other_count == 4 { fours[1-side] += sign }
  for n in neighbours_within_2(cell) (excluding the cell, inside the board): near[n] += delta
  hash_hi ^= HI[cell*2+side]; hash_lo ^= LO[cell*2+side]
```
Invariant tests: after every move of random games `score`/`fours` equal a from-scratch recount (for each window and each side with the other side's count 0: `score += W[count]`, `fours += (count==4)`); undoing all moves restores `cells, counts, near, score=[0,0], fours=[0,0], stones=0, hash=0,0`; transposition gives equal hashes.
`from_bitboards(black, white)`: for cell 0..225 ascending: black bit -> `place(cell,0)`, else white bit -> `place(cell,1)`. Bit `c` is byte `c>>3`, bit `c&7`; 29 bytes per colour (`ceil(225/8)`).
Queries:
- `wins_at(cell, side)`: exists window of `cell` with `counts[side]==4 && counts[1-side]==0`. (Five OR MORE, an overline wins; must agree with `check_win` on random positions.)
- `cell_value(cell, side, defense_factor) -> f64`: over windows of `cell`: `if other==0 { attack += W[own+1] }`, `if own==0 { defense += W[other+1] }`; result `attack as f64 + defense_factor * defense as f64`. Vector: stone white at cell 1, `cell_value(0, black, 0.5) == 2 + 0.5*(10+1+1) = 8.0`.
- `candidates(out)`: ascending cells with `cells[c]==0 && near[c] > 0`. Vector: a single black stone at cell 0 -> `[1, 2, 15, 16, 17, 30, 31, 32]`; empty board -> 0 candidates.
- `winning_cells(side, out, limit)`: ascending cells, empty, `near>0`, `wins_at`, stop when `length == limit`. Vector: black `(3..6, 7)` -> `[cell(2,7), cell(7,7)]`; `limit 1` -> 1; white -> 0.
- `fours` vector: black `(3,4,5,6;7)`: `fours[0]=2`; white at `(7,7)` -> 1; white also at `(2,7)` -> 0.

## 5. Transposition table (bit-exact policy)

`TranspositionTable::new(tt_bytes: i64)`: `fit = floor(max(0, tt_bytes) / 16)`; `entries = 0 if fit == 0 else 2^floor(log2(fit))`; storage `entries * 4` i32 words (16 B per entry; allocation never exceeds `tt_bytes`); `mask = entries - 1`. Allocated PER MOVE (one `Search`), zero-initialised; never shared between moves.
Entry layout (4 x i32 at `slot = (hash_lo & mask) * 4`): `[hash_hi, hash_lo (the check), score, packed]`, `packed = depth | bound << 6 | (move + 1) << 8 | (age & 0xff) << 16`; `packed == 0` means an empty slot. `move` is -1 for none (stored as 0) else the cell (<= 224, 8 bits). `hash_lo & mask` is done on the signed i32 (mask is non-negative so the result is non-negative; in Rust `(hash_lo as u32 & mask as u32)`).
- `probe(hi, lo)`: `entries == 0` -> -1; slot as above; hit iff `packed != 0 && data[slot]==hi && data[slot+1]==lo`, else -1.
- Accessors: `depth = packed & 0x3f`; `bound = (packed >> 6) & 3`; `move = ((packed >> 8) & 0xff) - 1`; `score = data[slot+2]`.
- `store(hi, lo, depth, bound, score, move, age) -> bool`: `entries == 0` -> false. `clamped = min(depth, 63)`. Read slot's `packed`; `stored_age = (packed >> 16) & 0xff` (logical), `stored_depth = packed & 0x3f`. **Keep the old entry (return false) iff `packed != 0 && stored_age == (age & 0xff) && stored_depth > clamped`.** Otherwise overwrite all four words, return true. (So: replace when empty, from an earlier iteration (age differs), or not deeper; same-age deeper entries survive. No buckets, no probing of neighbours.)
Table vectors (`transposition-table.test.ts`): bytes -> entries `0->0, -5->0, 15->0, 16->1, 100->4, 1<<20->65536`; `bytes() = entries*16 <= requested`; zero table stores nothing (`store` false, `probe` -1); round trip `store(-7, 99, 5, LOWER, -123456, 224, 3)` returns depth 5, LOWER, -123456, move 224; `store(8,100,0,UPPER,1,-1,3)` -> move -1; probe miss when either key half differs; depth 100 clamps to 63; single-entry table: same age deeper kept (false), same depth replaced (true), deeper new replaced, deeper entry of an earlier age (age 1 vs 2) replaced.
The search result does NOT depend on the table size in the tested cases (4 sizes give the same move), but does depend on its policy through cutoffs; reproduce it exactly.

## 6. Level 1 (`choose_level1(board, side, rng) -> MoveChoice`)

Precondition: at least one stone and one empty cell.
```
cands = board.candidates()           // ascending cells
values[i] = board.cell_value(cands[i], side, 0.9)      // f64
best = max(values)
block = None
for i in 0..n (ascending):
    if board.wins_at(cands[i], side): return {cell: cands[i], score: values[i], reason: Win}        // FIRST own winning candidate wins
    if block.is_none() && board.wins_at(cands[i], 1-side): block = Some(i)                         // FIRST blocking candidate
if let Some(i) = block: return {cell: cands[i], score: values[i], reason: Block}
threshold = best * (1.0 - 0.1)       // compute as f64 expression `best * (1.0 - 0.1)`
pool = indices with values[i] >= threshold (ascending)
picked = pool[floor(rng.next() * pool.len())]
return {cell: cands[picked], score: values[picked], reason: Heuristic}
```
All returns have `depth 0, nodes 0, stopped_by Completed`. Note the win scan returns at the first winning cell even if an earlier cell is a block (test "wins at once, even when the opponent also threatens").
Golden vectors (`level1.test.ts` + computed with the TS code): position black `(7,7)`, white `(8,8)` (moveCount 2), side black: `rng = 0` -> cell 98 (score 91.7), `rng = 0.999` -> cell 142 (score 90.7); black row `y=7 x=3..6` + `(0,14)` vs white row `y=3 x=3..6` -> reason Win, cell in `{(2,7),(7,7)}`; black `(2,3),(10,10),(12,12),(0,14)` vs white row `y=3 x=3..6` -> `cell(7,3)`, Block; black open three `(5..7,7)` vs white `(0,0),(14,0),(0,14)` -> cell in `{(4,7),(8,7)}`.

## 7. Level 2 (`search_level2(board, side, input) -> MoveChoice`)

`MoveChoice { cell, depth, nodes, score: f64-or-i64, reason: opening|win|block|heuristic|search, stopped_by: completed|soft|ceiling|nodes|stop }` (`score` is a float in level 1, an integer in level 2; the wire never carries it, only logs/tests do).
Input: `budget { soft_ms, ceiling_ms, max_depth, tt_bytes, max_nodes: Option }`, `rng`, `now() -> f64 ms`, `should_stop: Option<fn()->bool>`, `on_iteration: Option<fn(&MoveChoice)>`.
Score type: i64 (or i32 with `INF = i32::MAX/2`); JS `Infinity` is only used as alpha/beta sentinels and the TT-move ordering bonus; use a sentinel bigger than any score and take care that negation is safe.

### 7.1 `Search::new`
Fresh `TranspositionTable::new(budget.tt_bytes)`; `start = now()` (one call); per-ply buffers allocated lazily; `nodes = 0`; `stopped = None`; `has_result = false`; `age = 0`.

### 7.2 `run()`
1. `winning_cells(side, buf, 1) == 1` -> return `{cell: buf[0], depth 0, nodes 0, score WIN_SCORE-1, Win, Completed}`.
2. `threats = winning_cells(1-side, buf, 225)`; if `threats > 0`: `cell = best_of(buf[..threats])` = first strictly-greatest `cell_value(c, side, 1.0)` (ties keep the first); `score = if threats > 1 { -(WIN_SCORE-2) } else { 0 }`; return `{cell, depth 0, nodes 0, score, Block, Completed}`.
3. `root_moves = root_moves()`; `max_depth = min(budget.max_depth, 63)`; `result = None; stopped_by = Completed`.
4. `for depth in 1..=max_depth`: `age = depth`; `found = search_root(&mut root_moves, depth)`; `None` -> break. `result = {cell, depth, nodes: nodes_so_far, score, Search, Completed}`; `has_result = true`; call `on_iteration(result)`; if `|score| >= MATE_BOUND` break; if `depth < max_depth && now() - start >= soft_ms` -> `stopped_by = Soft`; break.
5. `stopped_by = stopped.unwrap_or(stopped_by)`. If `result == None` (no iteration completed, incl. `max_depth = 0`): `fb = choose_level1(board, side, rng)` and return `{..fb, nodes, stopped_by}` (reason Heuristic, depth 0, `nodes` = nodes counted so far). Else return `{..result, nodes /* total, including the aborted iteration */, stopped_by}`.
Hence `depth` of the answer = last COMPLETED depth; `nodes` = all nodes of the call.

### 7.3 `root_moves()`
`cands = candidates()`; for each in ascending order: `{cell, value: cell_value(cell, side, 1.0), tie: rng.next()}`; stable sort by `value` descending then `tie` ascending; keep the first `min(20, n)` cells.

### 7.4 `search_root(root_moves, depth)`
```
alpha = -INF; best_index = 0
for index, cell in root_moves:
    board.place(cell, side)
    score = -negamax(depth-1, -INF, -alpha, ply=1)
    board.remove(cell)
    if stopped.is_some(): return None
    if score > alpha: alpha = score; best_index = index          // strict: ties keep the earlier move
cell = root_moves.remove(best_index); root_moves.insert(0, cell)   // best first for the next iteration (others keep order)
return Some({cell, score: alpha})
```

### 7.5 `negamax(depth, alpha, beta, ply) -> score`
```
if should_abort(): return 0
nodes += 1
side = (root_side + ply) & 1;  opponent = 1 - side
if board.stones == 225: return 0
slot = tt.probe(hash_hi, hash_lo); tt_move = -1
if slot != -1:
    tt_move = tt.move_at(slot)
    if depth > 0 && tt.depth_at(slot) >= depth:
        stored = from_table_score(tt.score_at(slot), ply)
        match bound: EXACT -> return stored
                     LOWER -> alpha = max(alpha, stored)
                     UPPER -> beta  = min(beta,  stored)      // (the code's else branch: any non-EXACT, non-LOWER bound is UPPER)
        if alpha >= beta: return stored
moves = buffer[ply]
forced = board.fours[opponent] > 0
if forced:
    if board.winning_cells(opponent, moves, 2) > 1: return -(WIN_SCORE - (ply + 2))     // two blocks needed: lost
    count = 1; child_depth = depth                                                       // the single block does not use depth (extension, also at depth <= 0)
else:
    if depth <= 0: return board.score[side] - board.score[opponent]                       // static evaluation
    count = ordered_moves(ply, side, tt_move); child_depth = depth - 1
alpha_start = alpha; best = -INF; best_move = moves[0]
for i in 0..count:
    cell = moves[i]
    board.place(cell, side)
    score = -negamax(child_depth, -beta, -alpha, ply + 1)
    board.remove(cell)
    if stopped.is_some(): return 0
    if score > best:
        best = score; best_move = cell
        if score > alpha: alpha = score
        if alpha >= beta: break
if depth > 0:
    bound = if best <= alpha_start { UPPER } else if best >= beta { LOWER } else { EXACT }
    tt.store(hash_hi, hash_lo, depth, bound, to_table_score(best, ply), best_move, age)
return best
```
Notes: there is deliberately no check for "own immediate win" inside the tree (the parent either won or was forced; the root checks both first). `board.stones == 225` returns 0 BEFORE the TT probe. A forced node with `depth <= 0` still searches (it does not store in the TT because `depth > 0` is false). The forced-move buffer is the first opponent winning cell in ascending order.
`bound` uses the possibly TT-narrowed `beta`/`alpha_start` exactly as above (alpha_start is taken AFTER the TT adjustment of alpha).

### 7.6 `ordered_moves(ply, side, tt_move) -> count`
`cands = candidates()` into `moves[ply]`; `values[i] = if cell == tt_move { +INF } else { cell_value(cell, side, 1.0) }`; `width = min(12, count)`; partial selection sort:
```
for target in 0..width:
    top = target
    for i in target+1..count: if values[i] > values[top] { top = i }          // strict: first maximum
    swap moves[top] <-> moves[target]; swap values[top] <-> values[target]
return width
```
(The swaps move the displaced element to `top`; this permutation is part of the observable order of later picks, so do not replace it with a sort.) `values` buffers are `f64`/i64 per ply (the TT move uses `+INF`).

### 7.7 `should_abort()` (called at the top of every negamax call)
```
if let Some(max) = budget.max_nodes && nodes >= max { stopped = Nodes }
else if nodes % 1024 == 0:                         // nodes BEFORE this call's increment; so it fires on the very first node (nodes == 0)
    elapsed = now() - start
    if should_stop() { stopped = Stop }
    else if elapsed >= budget.ceiling_ms { stopped = Ceiling }
    else if has_result && elapsed >= budget.soft_ms { stopped = Soft }
return stopped.is_some()
```
The check is also repeated when already stopped, but after a stop every caller returns without another call, so the reason set first sticks. With `max_nodes = Some(0)`: first call stops with `Nodes` and no node counted. With `ceiling_ms = 0`: first call (nodes 0, elapsed 0 >= 0) stops with `Ceiling`. Soft only stops AFTER a completed iteration (`has_result`).
`max_nodes` makes a search deterministic across machines (no time dependence if `now` is constant): this is how tests and the arena run.

### 7.8 TT mate scores
`to_table_score(s, ply) = s + ply if s >= MATE_BOUND; s - ply if s <= -MATE_BOUND; else s`; `from_table_score(s, ply) = s - ply if s >= MATE_BOUND; s + ply if s <= -MATE_BOUND; else s`. Vectors: `to(WIN-5, 3) = WIN-2`; `from(WIN-2, 1) = WIN-3`; `to(-(WIN-5), 3) = -(WIN-2)`; `from(-(WIN-2), 1) = -(WIN-3)`; `to(1234,3)=1234`; `from(-1234,3)=-1234`. TT scores are stored in an i32 slot.

### 12.2 Resource probe (`BOT_FIXED_MEMORY_MB` -> process -> OS)
`read() -> {available_mb, source}`: fixed -> `clamp_bot_memory_mb(fixed)`, source `fixed`; else a cgroup-aware "available memory of the process" if known and `> 0` -> `clamp(bytes/1048576)`, source `process`; else OS free memory -> `clamp(freemem/1048576)`, source `os`. Injected as a trait so tests and the arena fix it. Read ONCE per game creation. (In Rust: read cgroup `memory.max - memory.current` / `/proc/meminfo` `MemAvailable`; document the choice. Node's own reading is `process.availableMemory()` then `os.freemem()`; the Node value in a container is cgroup-limited available memory.)

### 12.3 Admission (the "resource gate" a player can hit)
`BotAdmission::admit(level) -> BotStrength` called by `GameService::create` BEFORE anything is written or rate-counted, only when the opponent is `bot`:
```
if !BOT_ENABLED:                      refuse("disabled")             // not logged
reading = probe.read()
strength = if reading.available_mb >= BOT_MIN_AVAILABLE_MB { bot_strength_for(level, reading.available_mb) } else { None }
if strength.is_none():               refuse("memory", {availableMb, source})        // logs bot.refused
active = count active bot games now
if active >= BOT_MAX_ACTIVE_GAMES:   refuse("busy", {activeGames})                    // logs bot.refused
return strength            // frozen into the bot's seat
```
`refuse(reason, details)`: HTTP `503`, code `BOT_UNAVAILABLE`, message `BOT_UNAVAILABLE_MESSAGE` (the same single Polish text for every reason; the reason is NEVER shown to players), header `Retry-After: 60`. For `memory` and `busy` log one JSON line `{"event":"bot.refused","ts":ISO,"reason":...,...details}` at warn (`disabled` is silent).
Active games count (race-tolerant: two simultaneous creations may both pass by one):
```sql
select count(*)::int from games
where status = 'active'
  and exists (select 1 from game_players p where p.game_id = games.id and p.kind = 'bot')
  and <game_deadline("games")> > $now        -- turn_started_at + clock of the seat on turn, or, before the clock started, started_at + READY_DEADLINE_MS; classic branch only needed for F6
```
(An abandoned game nobody settled yet, past its deadline, must not hold a slot.) The count is global (all users), not per user.
Order inside `POST /api/games` (account): body parse (400) -> `admit` (503) -> `rate_limiter.hit("games-create:<user>", 10, 1h)` (429) -> `settle_for` -> transaction (user lock, delete seekers, close stale slots, insert) -> `409 ACTIVE_GAME_EXISTS` on the active-slot unique violation. Guest: body (400) -> client address (500 if unknown in production) -> `admit` (503) -> address rate limit (429) -> advisory lock on token hash, BR-13 (`409 ACTIVE_GAME_EXISTS`/`OWN_WAITING_GAME`) -> insert.

### 12.3.1 Compute gate (not visible to players)
`ComputeGate::run(task)`: strict FIFO, one task at a time per process; counts `pending` (queued + running; used by the show preflight only); a task that fails releases the gate. Singleton per process (in Node it lives on `globalThis`; in Rust a single `Arc<Semaphore>`/mutex in app state). Players never get an error from it: the move just waits.

### 12.4 Engine runner (`BotEngine::choose(turn) -> cell`, always a FREE cell)
`BotTurn {game_id, move_number, position, level, depth_cap, memory_mb, remaining_clock_ms, limits?}`.
```
queued_at = now()
gate.run(|| {
    remaining = turn.remaining_clock_ms - (now() - queued_at)       // the bot's clock ran while it waited for the gate
    if failures[game_id] >= 3: return inline_level1(turn)
    (level, budget) = budget_for({level, memory_mb, depth_cap, remaining, limits: turn.limits or configured})
    if budget.ceiling_ms <= 0: return inline_level1(turn)           // no time for a thread
    compute(...)
})
```
`compute` (Node: one worker thread per move): run `choose_move` with `rng_for(game_id, move_number)`, the budget, a stop flag polled every 1024 nodes, `on_iteration` recording the last completed iteration. After `soft_ms`: if an iteration exists, raise the stop flag; else remember "soft passed" and raise the flag at the FIRST completed iteration. After `ceiling_ms`: log warn `bot_ceiling`, play the last completed iteration's cell, else `inline_level1`. Result received after the ceiling is ignored and not logged. A worker that errors or exits without a move: record a failure for the game (`failures[game]++`, bounded map of 1000 games, a touched game becomes the newest), log error `bot_engine_error` `{event, ts, gameId, moveNumber, level, failures, error, message}` and play `last_iteration.cell` or `inline_level1`. After 3 failures in a game the bot plays `inline_level1` to the end (the preflight trial forgets its own id).
`inline_level1(turn)`: `choose_move` with level 1, budget `{0,0,1,0}`, `rng_for(game_id, move_number)`, returns `.cell`; on ANY error returns `first_free_cell` (lowest empty cell; -1 if none).
One info line per computed move (no position): `{"event":"bot_move","ts":ISO,"gameId","moveNumber","level","depth","nodes","stoppedBy","ms":rounded}`. Logs never carry the position.

### 12.5 Turn service (`BotTurnService::play_due_move(game_id) -> played|idle|busy|lost|failed`)
```
if in_flight.contains(game_id): return busy          // per-process set; inserted now, removed in finally
now = clock.now()
rows = PEEK (below, no lock, no pooled connection held during the search)
row = the bot row whose seat is on turn: black_seat is Some && seat_on_turn(move_count, black_seat) == bot_seat; none -> idle
due = status == 'active' && variant == 'classic' && started && move_count < 225        // (show games also need the pause; out of scope)
if !due: idle
move_number = move_count + 1
cell = engine.choose({game_id, move_number, position {decode(stones_black), decode(stones_white), move_count}, level: bot_level, depth_cap, memory_mb, remaining_clock_ms: remaining_ms.unwrap_or(0)})
game_move_service.play({player_id: bot_id}, game_id, {x, y, move_number})        // the SAME path as a human move: clock charge, win detection, finish, stats
-> played
catch AppError with code in {STALE_MOVE, GAME_FINISHED, NOT_YOUR_TURN, GAME_NOT_ACTIVE, GAME_NOT_STARTED} -> lost (silent)
catch anything else -> log error {"event":"bot.turn_failed","ts","gameId","error": name, "code"?: appError.code} -> failed
```
PEEK (unlocked read; one row per bot of the game):
```sql
select g.status, g.origin, g.variant, g.black_seat, g.move_count,
       g.stones_black::text, g.stones_white::text,
       g.turn_started_at is not null as started,
       p.id as bot_id, p.seat as bot_seat, p.bot_level, p.bot_memory_mb, p.bot_depth_cap,
       greatest(0, (case when p.seat = 1 then g.clock_ms_1 else g.clock_ms_2 end)
         - floor(extract(epoch from ($now::timestamptz - g.turn_started_at)) * 1000))::int as remaining_ms
from games g join game_players p on p.game_id = g.id and p.kind = 'bot'
where g.id = $game_id
```
(`started` = the clock runs = the human opened the game, `START_CLOCK_SQL`; `remaining_ms` NULL before that, then treated as 0 — but a not-started game is `idle` so the engine is never asked.) The bot's move time is charged by `play` to the bot's clock (`now - turn_started_at`), including the time spent computing and waiting for the gate; the search budget is already cut by the remaining clock (section 9.2).
Idempotence: two concurrent computations are harmless because `play` uses the conditional `UPDATE ... WHERE move_count = ?`; the loser gets `STALE_MOVE` (`lost`). Determinism of the seed means a recomputed move picks the same cell for the same node-limited budget (time-limited budgets may differ).

### 12.6 Scheduling (who triggers it)
- `POST /api/games/{id}/moves`: after `play` succeeds, `if bot_on_turn(state) { schedule_bot_turn(game_id) }`; the response never waits. (`bot_on_turn`: `status == "active"` and some player `kind == "bot"` with `seat == turnSeat`.)
- `GET /api/games/{id}` (state): same check after building the state; this covers the very first bot move when the bot is black (the clock starts at the human's first read, `START_CLOCK_SQL`, which happens inside `get_state`), a restart, and a lost computation. Polling every 750 ms while the bot is on turn makes recovery fast.
- `schedule_bot_turn`: spawn a detached task (`tokio::spawn`) with a FRESH request scope/connection (the handler's is done) running `play_due_move`. Errors are logged, never propagated. Only the route layer schedules; services never spawn.
- NOT triggered: `resign`, `get_state` of a finished game, show/MCP paths. A game nobody reads does not advance; its bot clock runs and lazy settlement/cleanup handle it.

## 13. HTTP API

### 13.1 `POST /api/games` with a bot
Body (account: optional; guest: required with `acknowledgedGuestWarning`): additional fields `opponent?: "human" | "bot"` (default human), `botLevel?: 1 | 2`.
Validation (Zod semantics; `400 VALIDATION` with `fieldErrors`/`fieldIssues`; shape first, refinement only when the shape is valid):
- `opponent` not in `{human, bot}` -> field `opponent`, message `Nieprawidłowy przeciwnik.` (code `invalid_value`).
- `botLevel` not literally `1` or `2` (a string `"2"` is invalid) -> field `botLevel`, `Nieprawidłowy poziom bota.` (code `invalid_union`).
- Refinement (`check_opponent`), emitted in this order:
  1. `opponent != "bot"` and `botLevel` present -> `botLevel`, code `BOT_LEVEL_WITHOUT_BOT`, `Poziom bota wybiera się tylko w partii z botem.` (and stop).
  2. `opponent == "bot"` and no `botLevel` -> `botLevel`, `BOT_LEVEL_REQUIRED`, `Wybierz poziom bota.`
  3. `opponent == "bot"` and `(variant or classic) != classic` -> field `opponent`, `BOT_VARIANT_UNSUPPORTED`, `Bot gra tylko w wariancie klasycznym.`
  4. `opponent == "bot"` and `isPublic == true` -> field `isPublic`, `BOT_PUBLIC`, `Partia z botem nie może być publiczna.`
  A `timeControlMs` with a classic variant is already refused by the F5 settings check (`TIME_CONTROL_CLASSIC`), so a bot game cannot carry a time.
- `resolve_opponent`: `opponent == "bot"` -> `{bot, level: botLevel or 1}`, else human.
Success `201`: `{ "gameId": "<uuid>", "opponent": "bot", "bot": { "level": 1|2, "name": "Bot · poziom 2 · 16 MB" } }` — NO `invitation`. (The human response keeps `{gameId, invitation: {...}}`; the union is discriminated by the presence of `invitation`.) Guest: a cookie is set like for any active game (`guestCookieMaxAge(active)`), status `active`.
Errors: `503 BOT_UNAVAILABLE` + `Retry-After: 60` (envelope code `BOT_UNAVAILABLE`, message above); `429 RATE_LIMITED`; `409 ACTIVE_GAME_EXISTS` (BR-13: the bot game occupies the creator's slot; a guest also `OWN_WAITING_GAME`); `400 VALIDATION`.
Game row created: `origin = 'bot'`, `is_public = false`, `status = 'active'`, `started_at = now`, `black_seat = draw(1|2)`, `variant 'classic'`, `time_control_ms 600000`, `clock_ms_1 = clock_ms_2 = 600000`, `created_at = now`; `turn_started_at` NULL (the clock starts at the human's first read). Players: seat 1 creator (account: `kind 'account', user_id, display_name` as of creation; guest: `kind 'guest', guest_token_hash, nickname`), `is_active true`, `joined_at now`; seat 2: `kind 'bot', bot_level, bot_memory_mb (level 2 only), bot_depth_cap (level 2 only), is_active true, joined_at now, seen_at now` (the bot counts as having opened the game; `join_channel` of the Node agent columns does not exist in this schema). No `invitations` row, no lobby seeker. `paper_game_states` is not inserted (classic only).
Guest created games: nothing else changes (`acknowledgedGuestWarning` still required; the confirm text says the game is not kept in history, 13.4).

## 18. Ambiguities and risks

1. **Bit-exactness of the arena depends on every tie-break** (selection sort swaps, `strict >`, stable root sort with rng ties, TT replacement, abort timing: `nodes % 1024` read BEFORE the increment, `nodes >= max_nodes` read at node entry). A single deviation changes game records but usually not strength; port in the order given and verify with the vectors of 7.9 and the small arena game of 19.3.
2. **`should_abort` re-entry:** after a stop, TS never calls negamax again, so the stop reason is stable; keep the early returns.
3. **Float scores of level 1** (`0.9 * defense`, threshold `best * (1 - 0.1)`) must be computed with the same operation order in `f64` (no fused multiply-add: Rust does not emit FMA by default, keep it that way; avoid `mul_add`).
4. **Spec vs code:** the spec says the bot's seat has `join_channel = 'web'`; the Rust schema has no such column (F3 dropped agents) — omit. Spec lists `bot: {level, memoryMb}`; the code adds `tableMb` (E15-S04) — return all three. The spec says "gracz gość w nagłówku ostrzeżenia" about no history; the code implements it as `play.botNotKept` on the guest form only.
5. **First bot move when the bot is black** depends on the human's first state read (the clock starts then, `START_CLOCK_SQL`); if the Rust `get_state` does not start the clock in the same call before `bot_on_turn` is evaluated, the first move is delayed by one poll (<= 2 s). Evaluate `bot_on_turn` on the state AFTER the clock start (as Node does: it uses the returned state).
6. **Admission race:** limit is checked outside the creation transaction (can overshoot by one), accepted in the spec. The count query is global; its deadline SQL must treat a not-yet-started game (`turn_started_at IS NULL`) via `started_at + READY_DEADLINE_MS`.
7. **Time-limited searches are not reproducible** (depth reached depends on CPU speed); only node-limited ones are. Production uses time budgets; the seed makes only the random parts repeatable. Strength comparisons Rust vs TS must use the node-limited arena (section 19). Rust will be faster per node, so production depth will be higher than Node's at the same time budget; the spec targets (p95 level-2 move <= 1800 ms, ceiling + 250 ms max, event-loop delay) were for Node and need re-measuring if you keep the limits.
8. **Worker kill:** Node kills the thread at the ceiling; Rust cannot. The engine already polls the ceiling every 1024 nodes (<= a few ms), so a cooperative stop is equivalent; `BOT_TERMINATE_WAIT_MS` and `resourceLimits` have no counterpart. Memory: the TT is allocated per move (up to 64 MiB for tier >= 3072 MB) and freed after; three concurrent games are serialized by the gate, so at most one table is live.
9. **`stones_black/white` representation** differs between Node (`::text` of a bitboard column) and whatever the Rust F3 schema uses; the engine needs 29-byte bitboards (225 bits, LSB-first per byte).
10. **Memory probe in containers:** the Node value is the cgroup-aware `process.availableMemory()`; the Rust equivalent must read cgroup v2 `memory.max`/`memory.current` (or v1) with `/proc/meminfo` as the fallback. Wrong reading changes the frozen tier (strength) and can refuse games (<256 MB).
11. **`best = -Infinity` in a node with zero candidates** (cannot happen on a non-full 15x15 board with a stone; TS would store `-Infinity|0 = 0`). Treat as unreachable; do not add handling that changes other behaviour.
12. **Show mode / bot-vs-bot / preflight / bot-bench** are not covered; `BOT_L*` limits and `bot_failures` are shared with them in Node.
13. **Level-2 default `ttBytes` for arena is 1 MiB while production tiers are 8-64 MiB**; the arena measures the engine at a much smaller table; larger tables change cutoffs, so production strength is not exactly the arena's.
14. **`GAME_NOT_STARTED`** is in the lost-race set but only appears in show/agent flows; keep it in the list.
15. **No timers anywhere:** a bot game nobody reads never advances; a bot clock can expire in an unread game (lazy settlement, F3). This is by design (spec R1).
